Inside LLM Bias V3

The question: do AIs favour posts written by their own AI? Three AIs each play the same 100 made-up Americans on a pretend Reddit. First every user gets the chance to write posts. Then every AI's users read every AI's posts and react. Nobody is ever told which AI wrote a post.

This page explains how the sim works, one step at a time, and lets you see everything it used and made: the exact words each AI was shown, every answer from every user, every code file, every command, and every output file. The numbers and comparisons are on the second page, LLM Bias V3 Data.

100users, the same 100 people as V1 and V2
3AIs: gemma3:12b · llama3.1:8b · qwen3:8b
320posts: gemma {{v3_posts_gemma}}, llama {{v3_posts_llama}}, qwen {{v3_posts_qwen}}
9worlds per run: each AI reads each AI's posts
2runs: V3, and V3a = the same posts read again with the action list in a new order
screens saved, every one viewable below
01 · The sim, step by step

How V3 works, explained from the start

Some words first. An AI is a program that writes text (like ChatGPT); here three of them run on a computer called the Spark. A user is one of 100 made-up people. A prompt is what the AI is shown. An action is something a user can do, like upvote or comment. Every answer the AI gives is a short list of actions in a fixed format (JSON).

  1. Meet the 100 users

    Each user is a made-up American with a written description: age, job, where they live, what they like, how they talk, and how they feel about 5 topics (politics, business, science and tech, entertainment, sports), from LOVE to HATE. The 100 were built from real US Census and survey numbers, so they look like the country. They are the same 100 people in V1, V2 and V3. Here is user 0, word for word:

    
      
    
    2. 
    
  2. 
      
    One AI plays every user, one at a time
    
      
    The three AIs: gemma (gemma3:12b, Google), llama
      (llama3.1:8b, Meta), qwen (qwen3:8b, Alibaba). One AI at a time plays all 100 users.
      For each user the AI gets two messages:
    
      
    • The system message (who you are): the same text for every user, with that user's description pasted in.
      • 
      
    • The user message (what is on your screen): the screen, the list of actions, and how to answer.
    
      
    Every user is a brand-new question. The AI does not remember the user before, and it is never told which AI it is.
    
      
    
    3. 
    
  3. 
      
    Posting time
    
      
    Each user opens an empty Reddit. The screen says the feed is empty and adds one line: "It's posting time: share
      whatever you'd post. Everyone will read the new posts afterwards." It lists the 5 topic communities and all the
      actions. The AI answers for the user with a list of actions. Every create_post in the answer becomes a post. A
      user can write 0, 1, 2 or more posts. Nobody is told to post. Section 02 shows the exact prompt and every answer.
    
      
    
    4. 
    
  4. 
      
    Three piles of posts
    
      
    Each AI's posting turn makes one pile, its post set: gemma's users wrote {{v3_posts_gemma}} posts, llama's
      {{v3_posts_llama}}, qwen's {{v3_posts_qwen}}. Posts are never mixed between piles. A post only ever says which user wrote
      it, never which AI.
    
      
    
    5. 
    
  5. 
      
    Nine worlds
    
      
    Now every AI reads every pile. A world is one reading AI playing all 100 users, reading the pile of posts that one AI's users
      wrote. 3 reading AIs × 3
      piles = 9 worlds. Each world starts fresh with only its pile, and is thrown away when it ends, so nothing in one world is
      seen in another. When an AI reads its own AI's pile (gemma reads gemma's posts), that world is a baseline.
    
      
    
    6. 
    
  6. 
      
    Your scroll: which post you see first
    
      
    Every user reads every post in the pile except their own. The order: the pile is shuffled once (with a fixed
      seed, so it is the same for all three reading AIs). Picture the posts in a circle. User 0 starts at the top of the circle,
      user 50 starts halfway round, and so on: each user's starting point is user number × number of posts ÷ 100. From
      there they go once around the circle, skipping their own post. So every post is read early by some users and late by
      others. Section 03 shows every user's scroll.
    
      
    
    7. 
    
  7. 
      
    Reading one post
    
      
    The AI sees one post at a time: the community, who posted it, the title and text, the comments other users have left
      (with IDs like [c12], the 5 newest), a note if a private message is waiting, then the list of actions and how
      to answer. Vote counts are never shown. The AI answers with the actions this user takes: upvote, comment, follow the
      poster, search, do_nothing, and so on. Section 04 takes the screen apart piece by piece.
    
      
    
    8. 
    
  8. 
      
    The timeline: everyone scrolls together
    
      
    Time moves in ticks. In tick 0 every user reads the first post of their scroll. In tick 1, the second. And so on,
      until every scroll is done. What a user does in a tick (a comment, an upvote, a follow, a message) shows up for
      other users from the next tick on; users see their own actions at once. So in tick 0 there are no comments
      anywhere, just like V1. Later on, posts carry more and more comments. Section 05 shows the life of any post, tick by tick.
    
      
    
    9. 
    
  9. 
      
    Extra screens and refresh
    
      
    Some actions open another screen: search_user shows up to 3 profiles (where a private message can be sent),
      search_posts and trend show lists of posts, open_messages shows the inbox,
      listen_from_group shows group chats, open_post opens a post from a list. The AI answers again there.
      At most 4 extra screens per post, then back to the scroll. If a user picks refresh without reacting to the
      post, the post comes back after the next one (at most 5 looks). Only llama did that: {{returns}} times in V3.
    
      
    
    10. 
    
  10. 
      
    Two runs: V3 and V3a
    
      
    V3 shows the action list in V1's order (upvote first). V3a reads the very same posts with the very same
      users again, with one change: the action list is put in a new order, the actions used least in V3 on top and the most
      used at the bottom (upvote last). Everything else is identical. Section 06 shows both lists.

03 · How the posts reach each user

  
Every user's scroll, in order

  
This is computed with the same code the sim used () and
  checked against the saved data: every user in every world of both runs read their posts in exactly this order
  (). The order depends only on the pile and the user, never on the reading AI, so it is the same
  in all three worlds that read a pile, and the same in V3 and V3a.

  
    
    
  1. Shuffle the pile once
    The posts are sorted by their key, then shuffled with a fixed seed made from the round
      and the pile's AI. Same pile, same shuffle, every time.
    2. 
    
  2. Each user gets a starting point
    Start = user number × posts in the pile ÷ 100, rounded down. With 119 posts,
      user 0 starts at position 0, user 1 at 1, user 50 at 59.
    3. 
    
  3. Go once around, skipping your own post
    From the start to the end of the shuffled pile, then from the top
      back to the start. A user who wrote 2 posts in this pile skips both.
    4. 
    
  4. One post per tick
    The scroll's 1st post is read in tick 0, the 2nd in tick 1, and so on. A refresh return
      (llama only) puts that post back one place later, which pushes the rest of that user's scroll one tick later.

05 · The timeline

  
How the ticks work, and the life of one post

  

    
Who goes, and when

      
    
        
  • Every user goes in every tick until their scroll is done. Nobody sits out and nobody goes twice.
    • 
        
  • 8 users are answered at the same time (the Spark runs 8 questions at once), in no fixed order. The order does
        not matter, because what anyone does in a tick is only seen by others from the next tick.
    • 
        
  • What carries over: comments, upvotes and downvotes, follows, mutes, reposts, quotes, new posts, group chats and
        private messages. A user sees a notice when a private message or group message is waiting.
    • 
        
  • Vote counts are never shown, only comments. trend uses the upvotes to rank posts.
    • 
        
  • How long: a pile of 99 posts takes 98-99 ticks (each user reads 98 or 99 posts). Llama's refresh returns add a
        few ticks for a few users.
    • 
      

    
One tick for one user

      
    
        
  1. The next post of their scroll is drawn with everything others did before this tick.
    2. 
        
  2. The AI answers with a list of actions.
    3. 
        
  3. Each action is tried in the world. OASIS's rules decide if it works (a second upvote on the same post fails, a
        comment ID that does not exist fails). Failed actions are saved with the reason.
    4. 
        
  4. If an action opens another screen, that screen is drawn and the AI answers again (up to 4 times).
    5. 
        
  5. One row per screen is saved to the world's file, in the order the world changed.
    6.

07 · V1 → V3

  
What changed from V1, why, and what it did

  
V1 (rounds 101-102) was the first full Spark study. V3 changed four things. Three were first tested alone as
  "V1 + one change" (log 14.43-14.48, 20-23 Oct); the live world was tried in a 20-user pilot. The big sim then ran with all
  four on together. V3 is round 101 again: the same 100 users, and the posting turn uses the same random seeds as V1
  round 101.

10 · On the Spark

  
What happens in a run, in order, and how long it took

  
    
    
  1. Gordon starts it on the Spark
    v3_start.sh runs the 110-check preflight with the part's exact
      settings. Only on ALL CLEAR does it add the watchdog to cron and start v3_big.sh.
      
    2. 
    
  2. Each AI in turn: posting, then its baseline
    Only one AI is loaded at a time. V3: qwen's 100 users post
      (empty feed + the posting line), then qwen reads its own AI's posts. Then the same for llama, then gemma.
      
    3. 
    
  3. The six cross worlds
    qwen reads llama's posts, qwen reads gemma's, llama reads qwen's, llama reads gemma's,
      gemma reads qwen's, gemma reads llama's. Each world is built fresh with only that post set and thrown away after.
    4. 
    
  4. Inside a world
    Tick by tick, 8 users at a time: show the screen, ask the AI, apply its actions, open any
      follow-up screen, save one row per screen. The order of users inside a tick does not matter, because others' actions
      show only from the next tick. 
    5. 
    
  5. Noise floor (V3 only)
    Each AI reads the first 4 posts of each of its users again in its baseline world,
      with fresh randomness (400 screens per AI). It shows how much answers move by chance alone.
    6. 
    
  6. Done
    The log's last line is ARM 1 DONE (V3a: ARM 2 DONE). Gordon removes the
      cron line and copies the data to the Mac.
    7. 
    
  7. On the Mac
    v3_clean.py cleans each run. v3_report_data.py computes every number once; the Excel file, the data page and this page are built from that.
    8. 
    
  8. V3a
    The same 320 posts are copied. rank_menu.py ranks the menu from V3's choices, least used
      first (upvote last). Then the 9 worlds are read again, with no posting turn and no noise floor.
      
    9. 
  

  
The machine



    

      
Machine: NVIDIA DGX Spark "honda" at the UK CS department: a GB10 chip with 121 GB of memory shared by the CPU and
      GPU. Another user (hsa303) runs GPU training jobs on it, which made these runs about 3-4× slower than on a free Spark.

      
Engine: llama.cpp (build b1-5e03bdd), one server per AI, only one loaded at a time, 8 answers at once, 8,192
      tokens per answer slot.

      
Models: qwen3:8b and llama3.1:8b (the Ollama files), gemma3:12b (ggml-org's gemma-3-12b-it Q4_K_M file).
